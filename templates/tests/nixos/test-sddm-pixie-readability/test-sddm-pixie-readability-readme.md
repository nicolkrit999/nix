# test-sddm-pixie-readability

Builds the real `sddm-pixie` package (`modules/nixos/services/sddm/sddm-pixie.nix`) for light and dark
base16 schemes on white, black and mid-grey wallpapers and checks the **built theme files** for
readability: the header (date top-left, power bar top-right), the lock-screen clock and the
"Press any key" hint must stay readable whatever the scheme and the wallpaper. The module patches the
upstream theme at build time (colour extractor guard, backing rectangles behind the header, header text
colour, wallpaper-dependent lock dim), so only a real build shows whether the patches landed and
whether the result is readable.

| Theme (`myconfig.constants.theme.base16Theme`) | Polarity | Wallpapers |
|---|---|---|
| `gruvbox-dark` | dark | white, black, grey |
| `catppuccin-mocha` | dark | white, black, grey |
| `gruvbox-light-medium` | light | white, black, grey |
| `catppuccin-latte` | light | white, black, grey |
| `gruvbox-dark` + `themeConfig.accentColor` override (mid grey) | dark | white |

The schemes come from `pkgs.base16-schemes` through the real `modules/nixos/toplevel/stylix-nixos.nix`,
exactly as on the real hosts. The wallpapers are 64x64 PNGs generated by a `runCommand` that also
verifies the pixel colour.

## Run

```bash
bash templates/tests/run-tests.sh --only nixos-sddm-pixie-readability      # from the repo root
bash check-nixos-sddm-pixie-readability.sh                                 # from this folder
```

Expected result: PASS. A red check is a finding about the module (or upstream drift in the patched
theme): do not loosen the thresholds. About 1 min warm (13 NixOS evaluations, 13 small builds), cap 10 min.

## How it works

1. `01-scenario-sddm-pixie-readability.nix` evaluates one slim fake host (`host/`, `nixos-extra/`: only
   `services.sddm-pixie` and the real stylix module, no WM, no shell) and makes one `extendModules`
   twin per scenario that overrides `base16Theme`, `polarity`, `sddm-pixie.background` (a store path)
   and optionally `themeConfig`. It exposes the scenario matrix (palette, wallpaper colour and path,
   drv path) as `matrix` and the `sddm-pixie` derivations as `pkg.<scenario>`.
2. `check-nixos-sddm-pixie-readability.sh` builds all of them with one `nix build --keep-going` (falling
   back to one build per scenario, to attribute a failure), fetches each build log with `nix log` and
   runs `assert_output.py`.
3. `assert_output.py` reads only the **built files** (`theme.conf`, `Main.qml`, `components/Clock.qml`)
   plus the known wallpaper colour. It parses the QML (block structure, top-level properties, positions of
   assignments) and computes WCAG contrast itself from the hex values; the module's `magick`/`awk`
   measurement is not reused. Qt blends in sRGB space, so the dim, the 0.88 backing and the hint
   opacity are applied in sRGB and the result is converted to linear luminance.
4. Controls: the script copies one passing build, applies 13 mutations (14 when qmllint is available), each aimed at one property, and requires
   the named check to flip from pass to fail; two more controls feed the cross-scenario check with
   non-monotonic dims. A checker that cannot fail would turn this test red.
5. `qmllint` (Qt) is used only when `pkgs.kdePackages.qtdeclarative` is already in the store (it is a
   ~700 MB closure, so it is never fetched); otherwise the syntax lint is skipped with a message. The build
   log is skipped the same way when none is retained (`nix log`).

Modelling assumptions: the wallpapers are uniform, so blur and crop do not change the backdrop; the header
backing is composited over the dimmed wallpaper (it is drawn above the dim overlay); the lock clock colour is
checked as the accent (`Clock.qml` derives a brighter colour from it).

## Checks

Per scenario (13 scenarios):

| Check | Expected |
|-------|----------|
| build | `sddm-pixie` builds (the patch phase aborts via `--replace-fail` when upstream drift breaks a pattern) |
| `autoColor-off` | `theme.conf` has `autoColor=false` |
| `conf-colors-hex` | `accentColor`, `textColor`, `backgroundColor` are `#rrggbb` |
| `background-is-wallpaper` | `assets/background.*` is byte-identical to the wallpaper under test |
| `palette-from-scheme` (matrix scenarios) | `textColor` and `backgroundColor` are base00-base07 of the scheme and `accentColor` a palette colour, not the module's stylix-off defaults |
| `override-applied` (override scenario) | `theme.conf` carries the `themeConfig` override |
| `no-placeholders` | no `@` left in `Main.qml`, `Clock.qml`, `PowerBar.qml`, `theme.conf` (an unsubstituted `@HEADER_FG@`) |
| `extractor-guard` | the first statement of the colour extractor canvas' `onPaint` (not the avatar canvas) is `if (config.autoColor !== "true") return;` and every `container.extractedAccent =` assignment lies after it, inside that canvas, and at least one exists |
| `delay-start-conditional` | every `colorDelay.start()` is conditional on `config.autoColor === "true"` |
| `extractedAccent-defaults-to-accent` | `extractedAccent` starts as `config.accentColor`, `baseColor` is `config.backgroundColor` |
| `headerPower-is-PowerBar` | `id: headerPower` sits on the `PowerBar` |
| `header-backings` | exactly one backing `Rectangle` fills `dateText` and one fills `headerPower`, both `Qt.rgba(baseColor..., 0.88)`, each with a `z` below its target (`z: 100`) |
| `header-token` | `dateText` `color:` and `PowerBar` `textColor:` are the same token, `container.extractedAccent` or `config.textColor` |
| `header-contrast` | that token resolved through `theme.conf` has >= 4.5:1 against `backgroundColor` |
| `header-selection-rule` | the accent is chosen exactly when it has >= 4.5:1 against `backgroundColor`, else the text colour |
| `dim-values` | the black overlay's login dim is 0.8 and the lock dim is one of 0.4-0.9 |
| `header-on-backing` | header colour vs the 0.88 backing composited over the dimmed wallpaper (lock and login dim) >= 4.5:1 |
| `clock-accent-binding`, `clock-readable` | the clock is bound to `container.extractedAccent`; its accent has >= 3:1 against the wallpaper under the lock dim |
| `hint-readable` | the "Press any key" text (`config.textColor` at its `opacity:`) has >= 4.5:1 against the wallpaper under the lock dim |
| `effects-imported` | `Clock.qml` imports `QtQuick.Effects` when it uses `MultiEffect`, and so does `Main.qml` |
| `build-log` | the build log's `lock dim=` and `header fg=` equal the built files and there is no `no step passed` line (skipped when no log is retained) |
| `qmllint-syntax` | `Main.qml` and `Clock.qml` have no qmllint `syntax` diagnostic (skipped when qmllint is not in the store) |

Across scenarios:

| Check | Expected |
|-------|----------|
| lock dim per theme | black wallpaper ends at the weakest step 0.4, black <= grey <= white, and white is strictly above black |
| matrix coverage | at least one light and one dark scheme whose base00 vs base05 luminance matches the polarity label |
| header branches | both header colours (`container.extractedAccent` and `config.textColor`) occur in the matrix |

Controls (on a passing `gruvbox-dark` + white build; each mutation must make the named check fail):

| Mutation | Tripped check |
|----------|---------------|
| `autoColor=true` | `autoColor-off` |
| extractor guard removed / moved below the first statement | `extractor-guard` |
| unconditional `colorDelay.start()` | `delay-start-conditional` |
| `@HEADER_FG@` left behind | `no-placeholders` |
| one backing rectangle dropped / backing alpha lowered to 0.3 | `header-backings` |
| header colour set to `"white"` | `header-token` |
| accent set equal to the backing colour | `header-contrast` |
| lock dim lowered to 0.4 on the white wallpaper | `clock-readable` |
| login dim changed to 0.7 | `dim-values` |
| `import QtQuick.Effects` dropped from `Clock.qml` | `effects-imported` |
| hint opacity lowered to 0.2 | `hint-readable` |
| a brace added to `Main.qml` (only when qmllint is available) | `qmllint-syntax` |
| dims white = black, or black above the weakest step | lock dim per theme |
