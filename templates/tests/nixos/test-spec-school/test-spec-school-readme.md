# test-spec-school

Checks the `school` specialisation (`users/krit/nixos/specializations/school.nix`) on the real `nixos-desktop` and `nixos-laptop`. The specialisation is a dedicated account (`krit-school`, uid 1001, own home, own home-manager user, no `krit` user): isolated SSH and git identity, a secrets split that leaves nothing owned by the personal user, University-only davfs mounts, OneDrive via `rcloneMount`, forced tailscale, a University-only Zen profile, HiDPI scale, the plain (unwrapped) brave, vscode and intellij-idea packages with PWAs that launch `${pkgs.brave}/bin/brave --app=...`, the personal Claude/Discord stack that stays on (with its secrets owned by the school user), a one-line `allowed_signers`, a system-wide GitHub host key pin, the `xdg.userDirs` layout (Projects/Templates/Public kept, Music dropped) with the empty-leftover cleanup of the old `~/year` and `~/projects`, the yazi go-to keys, the generated distrobox scripts (including the host-side SQL Developer RPM resolver and the stage-to-`~/.cache/school-distrobox` helper) and two new units (`school-claude-sync`, `school-dotfiles-clone`). Eval plus local bash runs of the generated scripts, no builds.

## Run

Via the suite runner (from the repo root): `bash templates/tests/run-tests.sh --only nixos-spec-school` (name as shown by `--list`); the direct command is below.

From repo root:

```bash
bash templates/tests/nixos/test-spec-school/check-nixos-spec-school.sh
```

From inside the directory:

```bash
bash check-nixos-spec-school.sh
```

`FLAKE_ROOT=<path>` evaluates another copy of the repo. Both hosts evaluate in parallel; about 77 s standalone (2026-11-02), 30 s with a warm eval cache after the LocalSend and pinned-apps mutants were added. The script re-executes itself inside `nix shell` (jq, rsync, git, util-linux, grep, coreutils) when one of those tools is missing from `PATH`.

## How it works

`01-scenario-spec-school.nix` reads the real `nixosConfigurations.<HOST>` (`HOST` env var) and its `specialisation.school` config; the spec's own user is `c.myconfig.constants.user` (home-manager is read under that name, the base under the base user's name). `report` is one `label<TAB>result` line per check (`ok` or `FAIL: <detail>`). `scripts` is the JSON text of the generated `writeShellScriptBin` scripts; `drvs` lists the `writeShellScript` derivations (startup check, deep check, the `school-sqldeveloper-rpm-resolve` and `school-stage-file` helpers from the setup script's string context, the `school-dotfiles-clone` unit script) plus the school davfs mount points, the school home and the text of the `removeEmptySchoolLeftovers` activation; `sync` is the script text of the `school-claude-sync` system service.

The script writes each script to a temp dir and runs `bash -n` on it. For the two `writeShellScript` derivations it reads the text with `nix derivation show` (no build). Nothing secret is hardcoded: values are compared against each other (sops key path vs `IdentityFile`, git email vs `allowed_signers` principal vs the base host email, hyprland monitor scale vs rendered `uiScale`). The scale is asserted both as the exact rendered string (`toString 1.5` is `1.500000`) and parsed as a float. Controls prove the checks bite: the uiScale parser must reject a different scale, `bash -n` must reject a broken script, and an unquoted command must split into several arguments. The setup script is additionally run in the shell with `distrobox`/`podman` store paths rewritten to stub functions that log their argument count, so quoting regressions of the `bash -c` payloads are caught by behaviour, not text matching. The same is done three times for the SQL Developer RPM states: the resolver store path in the setup script is rewritten to a local copy of the helper (tools rewritten to `PATH`, so a stub `findmnt` can simulate a mounted or autofs-only directory; `/proc` is the cheap real mount without the RPM, a plain temp dir is not mounted), with `SCHOOL_OPENCLOUD_GENERAL_DIR` pointing at a directory whose name contains a space and the retry loop set to one try. The deep check is run the same way with a stub `podman`/`distrobox`. The staging helper (`SCHOOL_STAGE_DIR`, `SCHOOL_STAGE_MARGIN_BYTES` overrides, its hard-coded `PATH` line dropped so stub `cp` binaries win) is run directly for copy, reuse of a same-size file, replacement of another size, not enough space, failing and truncating `cp`, a missing source, a symlink at the destination and SIGTERM during the copy (exit 143, temp file gone); `cleanup_staged` is extracted from the setup script and run against a lone file, a file with a sibling, a symlink, a directory and an empty path; the `removeEmptySchoolLeftovers` activation text runs against a temp `$HOME` holding old empty, non-empty and symlinked `~/year/...` dirs, an empty `~/projects`, and the new-layout dirs that must survive. In the setup stub-run the container sees the STAGED copy (the stub records its content at install time) and the OpenCloud path is never passed to a container command. `school-claude-sync` is run against temp source/destination directories (owner/chown flags stripped) and `school-dotfiles-clone` against a temp `$HOME` with a stub `git`; each has a control (the sync without `--delete` keeps the stale file, a failing clone leaves nothing behind).
