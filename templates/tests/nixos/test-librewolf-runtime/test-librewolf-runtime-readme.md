# test-librewolf-runtime

Starts the REAL LibreWolf package headless with the `user.js` files and the `librewolf.overrides.cfg` generated by the config and checks what actually takes effect: effective prefs, pref existence in the shipped build, the Privacy allow-list permissions, and the exit wipe. It automates the live steps of the batch 11 LibreWolf design that `test-librewolf-profiles` (eval level) cannot reach.

## Run

Via the suite runner (from the repo root): `bash templates/tests/run-tests.sh --only nixos-librewolf-runtime` (name as shown by `--list`); the direct command is below.

From the repo root:

```bash
bash templates/tests/nixos/test-librewolf-runtime/check-nixos-librewolf-runtime.sh
```

Or from inside the directory:

```bash
bash check-nixos-librewolf-runtime.sh
```

Needs `nix`, `jq`, `python3`, `bash`, Linux. Builds (or fetches from the cache) the `librewolf` package; about 14 s warm. Runs in the `heavy-b` CI group (`test.conf`, timeout 20 min). Nothing is written outside a temp dir; the browser gets a throwaway `HOME`, no display or D-Bus and a dead proxy, so it never touches a real profile or the network.

## How it works

`01-scenario-librewolf-runtime.nix` exposes, for the real desktop config with LibreWolf forced on, the package (`finalPackage`), the allow-list file referenced by `permissions.manager.defaultsUrl` (copied through a derivation so it is built, no IFD) and both generated `user.js` texts, and the layout: every generated `home.file` ending in `/librewolf.overrides.cfg` (path and text) and each profile's directory relative to HOME. `check-nixos-librewolf-runtime.sh` builds them and calls `lw_runtime_checks.py` (stdlib only).

The Python harness starts `bin/librewolf --headless --no-remote --marionette --remote-allow-system-access` with the home-manager layout rebuilt under the throwaway HOME (profile at `HOME/<configPath>/<profile path>`, overrides file at its `home.file` path), the generated `user.js` (plus a free Marionette port, a dead proxy and `remote.prefs.recommended=false`: Marionette's recommended prefs write `network.captive-portal-service.enabled=false` into any pref without a user value, and the overrides file's `true` equals Firefox's default so it leaves none), talks to it over the Marionette socket in chrome context, and per session: reads every `user.js` pref back as the effective value and whether it has a default in the build, reads `Services.perms`, reads Gecko's shipped `resource://app/defaults/permissions`, seeds cookies (for every allow-listed origin and a subdomain of it, plus two unlisted hosts) and history, then quits like Ctrl+Q (`eAttemptQuit`). The cookie and history stores are read from the profile's sqlite files afterwards, so the shutdown wipe itself is what is measured. Four sessions: Default, Privacy, a control, and Privacy without the overrides file.

Origins are taken from the allow-list file at test time, never hardcoded. Form-history wiping is not covered: LibreWolf disables form history, so nothing can be seeded.

Pref validity: a pref in `user.js` that has no default branch value in the build is unknown to Gecko, with a short exemption list for real prefs that have no default registered (`browser.contentblocking.category`, `browser.download.dir`, `browser.download.lastDir`, `browser.tabs.warnOnCloseOther`, `ui.systemUsesDarkTheme`) the stylix `font.*` and `reader.*` families, and the overrides profile marker pref (read from the file, not hardcoded).

`browser.uiCustomization.state` is excluded from the parity comparison because the browser rewrites it.

## Checks

| Check | Expected |
|-------|----------|
| static: one overrides file | exactly one `librewolf.overrides.cfg` is generated |
| static: marker selects block | the overrides file reads one `getPref()` profile marker and each profile's `user.js` marker value has a block |
| static: default / privacy user.js vs `mozilla.cfg` | after applying the profile's overrides block on top of `mozilla.cfg` `pref()` (both run after `user.js` and win; `lockPref()` always wins), no pref ends at a different value than `user.js` asks for |
| static: allow-list file well-formed | TAB-separated `origin` rows, unique, value `1`, https or `about:` origins, at least one `persist-data-on-shutdown` row |
| runtime: default / privacy effective prefs | every pref in the generated `user.js` has that exact value after startup |
| runtime: default / privacy pref exists | every `user.js` pref is known to the shipped build (default branch value exists) |
| runtime: overrides file location | the browser's `autoadmin.global_config_url` is the file at the `home.file` path |
| runtime: privacy allow-list loaded | every origin in the allow-list file is a `persist-data-on-shutdown` permission in the running browser |
| runtime: privacy allow-list carries shipped defaults | every row of Gecko's `defaults/permissions` is also a row of the file (the file replaces them) |
| runtime: privacy shipped defaults active | the shipped default permissions (uitour, install, ...) are active in the running browser |
| runtime: privacy cookies seeded | all seeded hosts were present before quitting (non-vacuous) |
| runtime: privacy exit wipe | unlisted cookies and all history are gone after quitting |
| runtime: privacy keeps allow-list | allow-listed origins and their subdomains keep their cookies after quitting |
| runtime: default wipes nothing | all cookies and history survive quitting in the Default profile |
| control: static override check | a pref flipped against `mozilla.cfg` (first boolean `pref()` line, picked at test time) is flagged by the static check, an unknown pref is not |
| control: parity check | the same flipped pref is flagged by the runtime parity check |
| control: validity check | an injected unknown pref is flagged and nothing else is |
| control: without overrides file | a Privacy session without the overrides file loses at runtime exactly the prefs the static model (`mozilla.cfg` alone) predicts |
| control: wipe harness | with the allow-list added as runtime permissions, listed cookies survive, unlisted ones and history are wiped (proves the "keeps allow-list" check can pass) |
