##   Introduction

This document explains every possible programs/service that can be enabled using denix. It acts as a cookbook where you can see the possible recipes.
Critical warnings are included for specific modules that directly impact system functionality if disabled.

- When configuring a new host remember to add the `hardware-configuration.nix` to the excluded path in `flake.nix`
---




### Common Modules (NixOS + Darwin)

These modules work on both NixOS and Darwin hosts.

#### Top-Level

* **`cachix`**: Configures Nix to pull from (and optionally push to) a specified binary cache, resulting in much faster rebuilds (pre-built binaries instead of local compilation).
* **`nh`**: A fast, user-friendly wrapper for NixOS/nix-darwin rebuild commands.
  * **Warning:** The rebuild aliases (`sw`, `gsw`, `upd`, `swboot`, `swtest`, ...) call `nh os` / `nh darwin`, so disabling `nh` fails evaluation with an assertion (NixOS and Darwin) unless `constants.nixImpure` is true. With `nixImpure` the NixOS and Darwin aliases (`sw`, `upd`, `swfall`, `gswfall`, `swdry`, `swoff`, `gswoff`, ...) use `nixos-rebuild` / `darwin-rebuild --impure` instead; `swpure` stays pure and uses `nh` when enabled. Standalone home aliases (`sw`, `gsw`, `swdry`, `upd`, `nfc`) append `--impure` instead.

* **`stylix`**: Global theming engine that colors and styles almost every application automatically based on the constants.
  * **Warning:** Disabling this would cause massive graphical inconsistencies regarding general theming, polarity, and wallpaper.

* **`attic`**: Configures an Attic binary cache (`serverUrl`, `cacheName`, `publicKey`) as a substituter, with optional pushing (`push`) and a sops-provisioned auth token (`authTokenPath`). There is no default server: the build fails unless `serverUrl`, `cacheName` and `publicKey` are set.
* **`nix-sweeps`**: Installs `nix-sweep` and writes its presets with garbage-collection retention (`gcd`, `gcn`), which default to `nh.gcd` / `nh.gcn` so a host only sets them once on `nh`. Enabled by default.

#### Themes

* **`themes.catppuccin`**: Imports the catppuccin-nix theming modules for NixOS system-level and home-manager; on Darwin only the home-manager module is imported. Sets `catppuccin.enable = true` with `catppuccin.autoEnable = false`: catppuccin-nix gates every port on `enable`, so it must be on, while `autoEnable = false` keeps ports opt-in so only the ports explicitly enabled elsewhere in the repo are themed.

#### Command-Line Programs (`programs.`)

* **`programs.bash`**: No enable option; selected by `constants.shell`. Configures the Bash shell with Hyprland socket fixes, custom `.bashrc` loading, optional `tmux` autostart, and the fastfetch splash when `programs.fastfetch` is enabled.
* **`programs.atuin`**: Shell history search via atuin, integrated with whichever shell `constants.shell` selects (zsh, fish or bash). Ctrl-R is left to fzf (`--disable-ctrl-r`); atuin's search is bound to Ctrl-O, and the Up arrow keeps atuin's behaviour.
* **`programs.bat`**: A `cat` command alternative featuring syntax highlighting, line numbers, and Git integration.
* **`programs.claude-code`**: Sets up the Claude Code CLI tool: overlay, `pkgs.claude-code` plus bun/gh/nodejs/rtk, `CLAUDE_BINARY`. The `cowork` toggle (default `false`) enables `services.claude-cowork` on NixOS. Extension points (all empty by default, filled from the user or host side): `extraEnv` (static variables; when set, the single `claude` binary of standalone home builds is a wrapper exporting them before exec'ing `pkgs.claude-code`), `extraPackages` (standalone home), `extraGitIgnores` and `extraShellAliases` (fish abbreviations on fish, aliases on zsh/bash). Forced off in the secure-travel and guest specialisations.
* **`programs.neovim`**: Enables the home-manager Neovim program with the home-manager default package (`neovim-unwrapped`) and no aliases. Extension points (empty by default): `extraPackages` (tools on nvim's PATH), `extraPlugins` (plugins on the packpath) and `extraWrapperArgs`; everything else (`viAlias`/`vimAlias`, `withPython3`, `sideloadInitLua`, ...) is set on the same `programs.neovim` by the layer that enables it.
* **`programs.yazi`**: Enables the home-manager Yazi file manager with the shell integration of `myconfig.constants.shell` and the home-manager default wrapper name. Extension points: `extraPackages` (helper tools) and `extraInitLua` (prepended to `init.lua`); keymap, theme, settings and plugins are set on the same `programs.yazi` by the layer that enables it. On NixOS it also provides a plain `yazi.desktop` entry (terminal launch, `inode/directory`) at default priority, which a personal layer may override. Plugin sets are in `programs.yazi.plugins`.
* **`programs.alacritty`**: Enables the home-manager Alacritty terminal with cursor shape, blink and beam thickness from `constants.terminal.*`, and the colour wiring of the global theme: with `constants.theme.catppuccin` the catppuccin-nix port is enabled and the stylix target is disabled to avoid a clash, otherwise stylix themes it. No font family or package is chosen here. Everything else (font, opacity, cursor colours, vi-mode cursor) is set on the same `programs.alacritty` by the layer that enables it.
* **`programs.firefox`**: Enables the home-manager Firefox with one profile (`profileName`, default `default`) that stylix themes (`stylix.targets.firefox.profileNames` follows it). Search engines, extensions, preferences and the toolbar layout are set on the same `programs.firefox.profiles.<profileName>` by the layer that enables it. The module also wires the `firefox-addons` overlay (`pkgs.firefox-addons`, the Rycee add-on set) on NixOS, Darwin and standalone home, whether or not Firefox is enabled, because the Zen and LibreWolf layers read the same overlay.
* **`programs.kitty`**: Enables the home-manager Kitty terminal with cursor shape, blink and beam thickness from `constants.terminal.*`, an optional `fontSize` (default `null`, keeps the kitty or stylix size), and the same catppuccin/stylix switch as `programs.alacritty`. No font family or package is chosen here. Everything else (font, opacity, padding, cursor trail and colours, macOS option key) is set on the same `programs.kitty` by the layer that enables it.
* **`programs.ranger`**: Enables the home-manager ranger file manager with its stock configuration (no image previews, no extra helper packages). ranger ships its own `ranger.desktop`, which is what the `inode/directory` MIME default resolves to when `constants.fileManager = "ranger"`. Image previews, rifle rules, mappings, plugins and further settings are set on the same `programs.ranger` by the layer that enables it.
* **`programs.zathura`**: Enables the home-manager zathura PDF viewer with vim-style mappings (`j`/`k`/`h`/`l` scroll, `d`/`u` half page, `J`/`K` next/previous page, `+`/`-`/`=` zoom, `D` toggles page mode), the JetBrainsMono Nerd Font Bold 16 (installed, fontconfig on), the system clipboard as selection clipboard and page-aware scrolling. Themed by catppuccin zathura when `constants.theme.catppuccin` is true, by the stylix zathura target otherwise.
* **`programs.direnv`**: Enables the home-manager direnv with nix-direnv. Nothing else is set here; the `use_dev_env` / `use_combined_env` helpers are added by `krit.programs.direnv` on the same `programs.direnv`.
* **`programs.zen.browser`**: Enables the Zen Browser through the zen-browser flake's home-manager module with one `default` profile that stylix themes (`stylix.targets.zen-browser.profileNames`). Native Wayland rendering (`MOZ_ENABLE_WAYLAND`, not on Darwin), no telemetry, no auto-update and no default-browser check through policies; the OS default browser is left to `constants.browser` (`setAsDefaultBrowser = false`). Extensions, search, containers, spaces, pins, mods, keyboard shortcuts, preferences and further policies are set on the same `programs.zen-browser` / `programs.zen-browser.profiles.default` by the layer that enables it.
* **`programs.librewolf`**: Enables the home-manager LibreWolf with the profiles declared in `profileSettings` (attribute name = profile, value = its prefs; default: one empty profile `default`); stylix themes them (`stylix.targets.librewolf.profileNames` follows the names). Once any profile carries prefs, each profile also gets the `nixcfg.librewolf.profile` marker pref and `~/.librewolf/librewolf.overrides.cfg` re-applies every declared pref per profile after LibreWolf's own `mozilla.cfg` (whose `pref()` calls beat `user.js`); with no prefs declared neither the marker nor the file is generated. Search, extensions, ids, names and everything else about a profile are set on the same `programs.librewolf.profiles.<name>` by the layer that enables it; prefs set there directly (outside `profileSettings`) only reach `user.js`.
* **`programs.codex`**: Installs the OpenAI Codex CLI (a terminal-based coding agent) via the `codex-cli-nix` flake's overlay (`github:sadjow/codex-cli-nix`, installs `pkgs.codex`); the locked nixpkgs equals that flake's, so there is no second nixpkgs import. Ships as a self-contained native Rust binary with no runtime dependencies.
* **`programs.comma`**: Enables the `comma` (`,`) tool from nix-index-database, allowing any Nix package to be run ad-hoc without installing it (` , command`).
* **`programs.doom`**: Installs Doom Emacs via `nix-doom-emacs-unstraightened` with a bundled stock `doomdir` (upstream `init.example.el` / `config.example.el` / `packages.example.el` verbatim, so the install matches what a fresh `doom install` would produce). Uses `emacs-pgtk` on Linux (native Wayland, falls back to X11) and `pkgs.emacs` (NS/Cocoa) on Darwin. Sets `provideEmacs = true` so the `emacs` binary IS Doom, ships all tree-sitter grammars (`treesit-grammars.with-all-grammars`), and enables `experimentalFetchTree` to avoid "Cannot find Git revision" errors on Nix 2.19+. Doom state lives in `~/.local/share/nix-doom`.
  * **Warning:** Because `provideEmacs = true`, this module's `emacs` binary IS Doom Emacs. Installing vanilla Emacs in parallel (via `environment.systemPackages`, `home.packages`, or another module) will collide on the `emacs` / `emacsclient` binaries - one install will shadow the other depending on PATH order.

* **`programs.eza`**: A modern, colorful replacement for the standard `ls` command, featuring icons and Git status awareness.
* **`programs.fastfetch`**: Fully declarative fastfetch (via home-manager `programs.fastfetch.settings`) plus `pokemon-colorscripts`; self-contained, installs both. The logo is a `command-raw` that runs pokemon-colorscripts (no images). All colours come from the stylix base16 palette (ANSI-name fallback when stylix is off), and modules are grouped into coloured boxed categories (System, Desktop, Hardware, Connectivity & Audio) with the `user@host` title resolved at runtime. Options: `generations` (default `""`, only valid with `random`), `random` (`true`), `pokemon` (`"pikachu"`, used when `random` is false), `showName` (`false`), `bigPokemon` (`true`), `splashCommand` (the splash script on Linux, plain `fastfetch` on Darwin), `osIcon` and `boxWidth` (per-platform defaults: Linux `"󱄅"` / `70`, Darwin `""` / `69`). The bash, zsh and fish modules run the splash in interactive shells when this module is enabled, tmux-aware (shown inside tmux rather than in the outer shell that launches it).
  * **Warning:** An existing `~/.config/fastfetch` symlink or directory (e.g. from the old external-dotfiles mapping) must be removed once before the first rebuild, otherwise home-manager refuses to write `config.jsonc`.

* **`programs.fish`**: No enable option; selected by `constants.shell`. Configures the Fish shell environment initialization and launches the fastfetch splash when `programs.fastfetch` is enabled.
* **`programs.fzf`**: A highly efficient command-line fuzzy finder used extensively in shell aliases.
  * **Warning:** Disabling this would cause some shell aliases to not work.

* **`programs.fzf.nix-search-tv`**: Installs `nix-search-tv` with a cross-platform `ns` wrapper script that drives it through fzf (its index is no longer refreshed at activation), enabling interactive fuzzy search across nixpkgs, home-manager, and all other Nix package indexes with preview, homepage, and source-link actions.
* **`programs.git`**: The core version control integration and global user settings.
  * **Warning:** NixOS installs `git` system-wide anyway (`common-configuration-nixos.nix`); on Darwin/standalone home this module installs it. Disabling also drops git-lfs, delta and the repo's `.githooks` wiring, besides the global GitIgnores. The git identity is only written when the `gitUserName` / `gitUserEmail` constants are non-empty.

* **`programs.agent-reach`**: Declarative tooling for the Agent Reach Claude skill. Installs the `agent-reach` CLI (pinned to tag v1.5.0, built from source; `doctor` no longer rewrites the `~/.agents|.openclaw|.claude/skills/agent-reach` skill dirs, and ffmpeg is a PATH fallback), `mcporter` with a generated `~/.config/mcporter/mcporter.json` holding the keyless Exa MCP entry, `yt-dlp`, `~/.config/yt-dlp/config` with `--js-runtimes node`, and the Xiaoyuzhou transcription script at `~/.agent-reach/tools/xiaoyuzhou/transcribe.sh` (wrapped with its curl/perl/bc/ffmpeg/python deps; only the Groq key is missing). `gh` and `nodejs` come from `programs.claude-code`, which must be enabled (asserted). `browserChannels` (default false; on for the desktop and laptop) additionally installs `bili` (bilibili-cli), `twitter` (twitter-cli, pinned rev), `rdt` (rdt-cli, pinned rev), `opencli` (v2.0.1), `mcp-server-linkedin` (v4.25.1, patchright wheel with nixpkgs node, driven through Google Chrome, registered in mcporter as `linkedin-scraper`), and on x86_64-linux `xiaohongshu-mcp` (v2.5.5 plus its pinned fingerprint Chromium, user service `xiaohongshu-mcp` on `127.0.0.1:18060`, registered in mcporter as `xiaohongshu`); `browser-cookie3` is added to the agent-reach environment so Xueqiu reads the Chrome login. With `opencliExtension` (default true, only with `browserChannels`) the NixOS side force-installs the OpenCLI Chrome extension through `programs.chromium` policies. Only logins, cookies and keys stay manual (Twitter cookies or a Chrome login, Reddit/XHS/Xueqiu/Bilibili logins in Chrome, `mcp-server-linkedin --login`, XHS QR login, Groq key in `~/.agent-reach/config.yaml`). Forced off in the guest and secure-travel specialisations.
* **`programs.headroom`**: Installs the `headroom-ai` context-compression toolkit (cross-platform PyPI wheels for x86_64-linux, aarch64-linux, aarch64-darwin) plus `ast-grep` for code-aware compression. Provides the `headroom-wrap` alias (ephemeral inline proxy that dies with the session) and the `headroom-claude` script (probes `127.0.0.1:8787`, fails clearly if the proxy is down, otherwise execs `claude` through it with `ENABLE_TOOL_SEARCH=true`). Forced off in the secure-travel and guest specialisations. Auto-starts a background proxy on port 8787 - a systemd user service on NixOS, a launchd agent on Darwin - exposing a web dashboard at `http://localhost:8787/dashboard`.
* **`programs.herdr`**: Installs herdr (https://herdr.dev), a Rust terminal agent-multiplexer/TUI, via the `herdr` flake input tracking `github:ogulcancelik/herdr/master`. Deliberately tracks `master` rather than a pinned release tag, favoring a low-maintenance "don't think about updates" setup over reproducibility for this tool.
* **`programs.lazygit`**: A terminal-based GUI application to simplify complex Git commands (icons use `nerdFontsVersion` 2).
* **`programs.nltchNur`**: Installs a configurable list of NUR (Nix User Repository) packages as system packages, with support for permitting specific insecure packages via `permittedInsecurePackages`.
* **`programs.npm`**: Installs `nodejs_latest` and configures npm with a global prefix under `~/.npm-global`, adding it to `PATH` so globally installed packages are available in all shells.
* **`programs.shell-aliases`**: A centralized repository of command-line shortcuts deployed across bash, zsh, and fish. The `deadnix*` aliases run upstream HEAD (`github:astro/deadnix`). Cache push aliases pass the attic token via a token-file config (`attic.nix`) and the cachix token via a shell variable, never on argv.
* **`programs.sidra`**: Installs Sidra (https://github.com/wimpysworld/sidra), an Apple Music desktop client, via `home.packages` from its own `sidra` flake input (`inputs.sidra.packages.<system>.default`). The `customTheme` option (default `true`) declaratively generates Sidra's `custom-theme.json` from this repo's live Stylix/base16 colors, so its UI matches the rest of the desktop theme instead of using one of Sidra's bundled built-in styles.
  * **Warning:** With `customTheme` enabled, `custom-theme.json` is managed declaratively and any manual edits to it will be overwritten on the next rebuild. Set `customTheme = false` to freely pick one of Sidra's other bundled styles in-app instead.

* **`programs.starship`**: A fast, deeply customizable prompt for any shell, themed dynamically.
* **`programs.statix`**: Installs statix, a static analysis / linter for Nix code that catches common mistakes and anti-patterns.
* **`programs.television`**: Installs the `television` TUI fuzzy-finder (`tv`) with a `config.toml` (`tick_rate`) and runs `tv update-channels` on package change. `ns` is the separate `nix-search-tv` wrapper, not part of this module; there is no Nix channel.
* **`programs.thunderbird`**: Declarative Thunderbird with declarative email account setup, built on home-manager's `programs.thunderbird` and `accounts.email.accounts`. The module itself is non-opinionated - the actual account list is defined per-host via `myconfig.programs.thunderbird.accounts` and `myconfig.programs.thunderbird.sopsFile`. Email addresses and passwords never appear in the repo or the Nix store: each account's address is composed from two sops secrets (local part and domain) via `config.sops.placeholder`, and the profile's `user.js` is rendered at activation time through `sops.templates` rather than by home-manager.
  * **Warning:** The address must stay split across two sops secrets - home-manager types the address as `strMatching ".*@.*"`, but a sops placeholder contains no `@`, so collapsing the two secrets into one full-address secret fails to evaluate. The module also claims the Thunderbird profile directories in an activation script, since sops-install-secrets would otherwise create them root-owned and break home-manager activation.

* **`programs.tmux`**: A terminal multiplexer for managing multiple sessions, windows, and panes within a single terminal instance (copy uses `pbcopy` on Darwin, `wl-copy` on Linux).
* **`programs.vikunja-desktop`**: Installs `pkgs.vikunja-desktop`, the Electron desktop client for a self-hosted Vikunja to-do/task server, via `home.packages` on all platforms. On non-Darwin (Linux) hosts it additionally registers an `xdg.desktopEntries` entry and `xdg.mimeApps` association for the `x-scheme-handler/vikunja-desktop://` custom URL scheme - required for OAuth login callbacks to reach the app, since home-manager manages `mimeapps.list` as a read-only store symlink and without this the browser reports a successful login while the desktop app never receives the session. Darwin has no xdg-mime concept, so that branch is skipped there and only the package is installed.
* **`programs.discord`**: Installs the official Discord client with a client mod (Vencord or Equicord, option `mod`, default `vencord`; the krit layer selects `equicord`) through the `nixcord` flake input's home-manager module (`programs.nixcord`, OpenASAR on by default). On Linux the package is a thin shim around nixpkgs `pkgs.discord` (FHS env, so the host overlay and its `--password-store=gnome-libsecret` flag still apply and the flags are concatenated, not replaced); on Darwin Nixcord's own Discord package is used. Plugin settings are written to `~/.config/<Vencord|Equicord>/settings/settings.json` by a home-manager activation step (a writable copy, replaced on every switch). Vesktop is not managed by it.
* **`programs.yazi.plugins`**: Enables the Yazi file manager and configures it with a curated plugin set (the plugin module is imported on Linux and Darwin): starship prompt integration, `jump-to-char` (`F` key), and `relative-motions` with relative-absolute line numbers. The user config (`krit.programs.yazi`, not this module) also gives the Linux `O` open menu an extra **Open with** entry, second in every open rule (the first opener on Enter/`o` stays first): it runs the `yazi-open-with` helper, which lists the applications the system MIME associations know for the file (default marked with `*`) in an fzf popup titled `Menu` and launches the pick with `gtk-launch`. Not present on Darwin.
* **`programs.zoxide`**: A smarter `cd` command that tracks your most frequently visited directories.
  * **Warning:** Disabling this would cause some aliases to not work.

* **`programs.zsh`**: No enable option; selected by `constants.shell`. Configures the Zsh shell with common initialization settings, plus the fastfetch splash when `programs.fastfetch` is enabled.

#### Services (`services.`)

* **`services.tailscale`**: A zero-config mesh VPN service that builds secure networks between your devices. Adds the `tailscalenodeset` (pick the suggested exit node with LAN access) and `tailscalenoderemove` shell helpers. On NixOS it also opens the tailscaled UDP port, trusts the tailscale0 interface and sets loose reverse-path filtering (upstream `openFirewall` and `useRoutingFeatures = "client"`). On macOS it runs the nix-darwin tailscaled daemon and asserts that the `tailscale-app` Homebrew cask is not installed alongside it (the host uses the cask instead, and the darwin NAS modules assert that exactly one Tailscale provider is present via the internal read-only `myconfig.services.tailscale.darwinCaskPresent`).

### NixOS-Only Modules

These modules are only available on NixOS hosts.

#### Always-On Infrastructure

These modules are always active on NixOS hosts and handle platform integration. They are not toggled by the user.

* **`common-configuration`**: Core NixOS system baseline - sets hostname, locale/keyboard, fonts, essential system packages (git, curl, sops, etc.), automatic monthly btrfs scrub (one mount point per btrfs device, nothing on hosts without btrfs), GNOME Keyring/PAM integration (gnome-keyring is the sole Secret Service provider and gcr-ssh-agent the sole SSH agent, see `Documentation/usage/gotchas/secret-service-single-provider.md`), and boot tweaks. Always enabled.
* **`home-manager`** (NixOS-only): Sets the NixOS home-manager integration options: `useUserPackages = true`, `backupFileExtension = "hm-backup"` and `useGlobalPkgs = true` (home-manager shares the system `pkgs`; `nixpkgs.*` inside HM asserts on NixOS/darwin, so standalone-only `nixpkgs.*` is gated on `moduleSystem == "home"`). Always enabled on NixOS.
* **`nix`**: Configures the NixOS Nix daemon (flakes, store optimisation, extra binary caches and keys, `@wheel` as trusted users, automatic GC off because `nh` owns it) and the nix-index-database integration (the system-level layer is on, the home-manager `programs.nix-index` layer is turned off to avoid a duplicate). Always enabled.
* **`user`**: Declares the primary user account for NixOS (normal user from `constants.user`, login shell from `constants.shell`, groups `wheel` and `networkmanager`). uid and home directory are left to NixOS defaults. Always enabled.

#### System

* **`home-packages`** (toggle, enabled by default): Installs the host's chosen browser, terminal, editor, and file manager from `constants` as system packages, plus shared GUI utilities (cliphist). A role is looked up in `pkgs`, then `pkgs.kdePackages`; it is skipped when a program module already provides the package. There is no fallback package: when nothing resolves a role (for example the `zen-beta` browser, which comes from a flake) and no enabled module or home-manager package provides it, an evaluation warning is emitted instead of installing something unrelated.
  * **Warning:** Disabling this means the system does not automatically install the chosen browser, editor, file manager, and terminal based on the host preferences.

* **`bluetooth`**: Enables the system Bluetooth daemon and related utility packages.
* **`boot`**: Sets up the Plymouth boot splash screen and GRUB bootloader with UEFI support, OS prober, and multi-resolution graphics configuration, plus kdump crash-dump reservation, initrd systemd and a stale-GRUB-copy refresh on every rebuild.
* **`env`**: Exports system-wide environment variables (`BROWSER`, `TERMINAL`, `EDITOR`, `XDG_BIN_HOME`) derived from the host constants.
* **`kernel`**: Selects the kernel package set per host: `nixos-desktop` uses Zen (`linuxPackages_zen`), `nixos-laptop` uses `linuxKernel.packages.linux_testing`, and any other host uses the default `linuxPackages`.
* **`mime`**: Explicitly maps the defined default applications to file types across the system.
  * **File-family defaults**: the `mime` options `videoPlayer`, `audioPlayer`, `imageViewer`, `pdfViewer`, `docEditor`, `sheetEditor`, `slideEditor` and `archiveManager` (defaults `mpv`, `mpv`, `gwenview`, `zathura`, `libreoffice`, `libreoffice`, `libreoffice`, `ark`) each own a fixed list of MIME types. A value is a nixpkgs package name or a flatpak app id (e.g. `ai.storyteller.wordcraft`, desktop id `<id>.desktop`). `mime` installs the chosen package itself (skipped when a program module or home-manager package already provides it; nothing is installed for a flatpak id, `services.flatpak.packages` provides it). Guard: a value that is not a package, not provided by a module, or a flatpak id missing from `services.flatpak.packages` falls back to the role's default with one `mime: <role> = ...` evaluation warning. A role value ending in `.desktop` (e.g. `org.kde.kate.desktop`) is taken verbatim as the desktop id and counts as present when its package is listed in the `mime.extraAppPackages` option and resolves, or when it is a flatpak id in `services.flatpak.packages`; otherwise the same fallback applies.
  * **`mime.extraAppPackages`**: list of package names (resolved like role names: `pkgs`, then `pkgs.kdePackages`) that a host adds for role overrides whose package is not otherwise installed (e.g. `docEditor = "org.kde.kate.desktop"; extraAppPackages = [ "kate" ];`). They are installed once into `environment.systemPackages` (deduped against packages already provided by a module or home-manager); names that do not resolve produce a single `mime: extraAppPackages ...` warning and install nothing.
  * **Warning:** Disabling this would cause the shortcuts that open "browser, editor, file manager" to fail and/or open with the distro's fallback.

* **`net`**: Enables NetworkManager for network connectivity and installs `networkmanagerapplet`. Always enabled.
* **`qt`**: Configures Qt application themes, platform integrations, and rendering engines.
  * **Warning:** Disabling this would cause graphical inconsistencies in Qt applications.

* **`constants.timeZone`**: Not a module; the system timezone is set by `common-configuration` from the `timeZone` constant (default: `Etc/UTC`).
* **`xdg-portal`**: Always enabled, no toggle. Configures XDG desktop portals with per-desktop routing for screensharing, file picking and secrets (Hyprland, KDE, GNOME, COSMIC, niri and mango all have tailored configurations, plus a `common` fallback); see `Documentation/usage/gotchas/xdg-desktop-portal-nixos.md`.
* **`zram`**: Enables a compressed swap space in RAM to drastically improve system performance under memory pressure.
  * **Warning:** Enabled because it is beneficial everywhere.

#### Desktop Environments & Window Managers

* **`programs.cosmic`**: The COSMIC desktop (System76), configured declaratively through cosmic-manager. Covers keybinds (`extraBinds` for custom ones, `disabledDefaults` to unbind COSMIC defaults), `monitors` (per-output mode, scale, position, rotation and enable/disable with a `"*"` fallback, applied at login via cosmic-randr), wallpapers taken from `constants.wallpapers`, input (keyboard layout from the constants, numlock on; optional `keyboardRepeatDelay/Rate`, `touchpadTapToClick/NaturalScroll/DisableWhileTyping/AccelProfile/Speed` and `mouseNaturalScroll/AccelProfile/Speed`, all `null` = COSMIC default) and idle (screen off after `services.hypridle.screenOffTimeout`, no automatic suspend; COSMIC has no idle dim or lock), the colour theme (`followTheme`, default on: dark or light from `constants.theme.polarity`, palette from the base16 scheme, accent from base0D, a `themeAccent` slot such as `"base0E"`, or the catppuccin accent; colours only), and the panel and dock (a replaced Panel + Dock pair with COSMIC's default layout on all outputs; `pinnedApps` lists the dock's pinned applications, `.desktop` suffix stripped; `panelAutohide` and `dockAutohide` pick `Never`, `OnOverlap` or `Always`, defaults `Never` and `OnOverlap`).
* **`programs.gnome`**: The GNOME desktop environment, with optional extra app pinning and keyboard shortcut configurations: `extraBinds` for custom shortcuts and `wmKeybindings` for extra native window-manager shortcuts (`org/gnome/desktop/wm/keybindings`, e.g. workspace switching, maximize or minimize on extra mouse buttons; a list replaces the schema default of that key, so default accelerators are re-listed, and `close` is appended to the module's own `<Super><Shift>c`). The module frees `<Super>m` (the notification-list toggle `toggle-message-tray` now has no shortcut) so hosts can use it for `toggle-maximized`.
* **`programs.hyprland`**: A highly customizable, dynamic tiling Wayland compositor. The config is written in Lua (`configType = "lua"`), so `windowRules`, `monitorWorkspaces` and `extraBinds` entries are Lua-shaped attrsets. Includes monitor config, exec-on-start rules, workspace-to-monitor assignments, window rules, wallpaperd wallpaper management (mpvpaper for video/gif, awww for stills; see `Documentation/features.md`), and optional extra keybinds.
  * **Warning:** Enabled to have at least one WM.

* **`programs.kde`**: The KDE Plasma desktop environment; with catppuccin on it installs the matching catppuccin KDE colour scheme (flavour and accent). Includes optional app pinning, keyboard shortcuts, panel layout, krunner config, screen locker, and input settings.
* **`programs.mango`**: MangoWM - a dwm-inspired practical Wayland compositor. Configured with scrollable-tiling and master-stack layouts, full stylix color integration, per-monitor rules, built-in Xwayland for X11 app support, and wallpaperd wallpaper management (mpvpaper for video/gif, awww for stills). Includes optional keybinds and exec-once entries.
* **`programs.niri`**: A scrollable-tiling Wayland compositor with wallpaperd wallpaper management (mpvpaper for video/gif, awww for stills) and optional exec-on-start and keybind configurations.

* **`programs.tgt`**: Installs tgt, a Telegram TUI client, built in the module from the `tgt` flake input's source (`github:FedericoBruzzone/tgt`) against the current nixpkgs, so a flake update moves it (nixpkgs' `tgt` is an unrelated iSCSI target daemon). TDLib is pinned to the exact version the locked source's `tdlib-rs` needs (a local C++ compile, not in the binary cache); `test-workaround-guards` says when the pin is stale or removable. A wrapper seeds the default config into `~/.config/tgt/config` (or `~/.tgt/config` if a legacy `~/.tgt` exists) without overwriting user files.
* **`programs.vicinae`**: A Wayland application launcher with Raycast-style extensions, stylix theming, file search outside the root folder, and configurable extra extensions and packages. The privileged `vicinae-input-server` wrapper (paste-to-app and snippet expansion; it reads all keyboards and injects keys) exists only while vicinae is enabled and is executable only by the `vicinae-input` group, which holds just `myconfig.constants.user` (after the first rebuild the user must log out and back in before paste/snippets work).
* **`programs.walker`**: Installs the Walker (v2) application launcher as a service, with a stylix-coloured theme. Disabled on all hosts; vicinae is the launcher everywhere.

* **`programs.waybar-hyprland`, `programs.waybar-mango`, `programs.waybar-niri`**: A powerful, modular status bar for Wayland window managers, configured with workspaces, clock and window title, keyboard layout, weather, Wi-Fi, Bluetooth, audio, microphone, battery, (with `services.airplane`) airplane mode, (with `services.coffee`) coffee mode and (with swaync) notification modules. The airplane pill shows online / Wi-Fi off / airplane, left click toggles with the last chosen scope, right click opens the scope picker. None of the bars has a system tray. #### Services (`services.`)

* **`services.rcloneMount`**: Declares rclone remotes (`mounts`: name, remote, config file, mount point, VFS cache mode) as systemd user services that FUSE-mount them, creating the mount points via tmpfiles.
* **`services.airplane`**: Airplane mode for NixOS hosts with NetworkManager (on by default exactly when `networking.networkmanager.enable` is true; an assertion fails the build if it is forced on without NetworkManager). Installs `airplane`: with no argument it asks which mode to apply (Wi-Fi only off, full airplane, back online), applies it and prints the real state read back per radio (Wi-Fi, WWAN, Bluetooth and every other rfkill type) with a final verdict. `airplane wifi` runs `nmcli radio wifi off`; `airplane full` runs `nmcli radio all off` (kept across reboots by NetworkManager) plus `rfkill block all`; `airplane off` runs `nmcli radio all on` plus `rfkill unblock all`; `airplane toggle` goes back online when a mode is on, else applies the last chosen scope (stored in `$XDG_STATE_HOME/airplane-scope`, default full); `airplane pick` opens a vicinae dmenu list; `airplane status` prints the waybar JSON. Shell aliases `airplane-on` (= `airplane full`) and `airplane-off` (= `airplane off`). Each change sends a desktop notification and refreshes the waybar pill.
* **`services.audio`**: Configures the PipeWire sound server and related audio management tools.
* **`services.auto-cpufreq`**: Enables the auto-cpufreq daemon, an automatic CPU speed and power optimizer that dynamically adjusts CPU governors and turbo based on battery state and system load. Mutually exclusive with TLP.
* **`services.autotrash`**: Runs `autotrash` as a daily systemd timer to automatically delete files from the user's trash that exceed a configurable number of days (`retentionDays`, default: 30).
* **`services.coffee`**: Coffee mode for Hyprland, Niri and Mango hosts: `coffee-on`, `coffee-off`, `coffee-status` and `coffee-toggle` (used by the waybar pill click) keep the machine awake against automatic idle and lid events. Sets logind `SuspendKeyIgnoreInhibited` and `HibernateKeyIgnoreInhibited` so the suspend/hibernate keys still work while coffee is on. See the coffee-mode gotcha doc for what it does not block.
* **`services.hypridle`**: An idle management daemon for Wayland that automatically dims, locks, and turns off displays after configurable inactivity timeouts.
* **`services.hyprlock`**: Home-manager lock screen config (hyprlock, themed by catppuccin or stylix) plus its PAM service; active whenever Hyprland, niri or mango is enabled. Options: `use24HourClock` (default `false` = 12-hour with AM/PM; the clock and the date are one shared definition for the catppuccin and the plain variant: `$TIME12` / `$TIME` and `%A, %d %B %Y`, independent of `LC_TIME`) and, for the catppuccin variant only, the sizes `avatarSize`, `clockFontSize`, `dateFontSize`, `inputWidth`, `inputHeight` (defaults = the theme's own values) (defaults = the theme's own values; the avatar keeps a constant 42 px gap above the input field whatever the input height). Wallpapers follow `constants.wallpapers` (only `wallpaperURL`/`wallpaperSHA256`; `videoURL`/`gifURL` are ignored) on every monitor, with and without catppuccin: a monitor uses its own entry's `wallpaperURL`, else the `*` entry's, else the nix-black fallback (`fallbackWallpaperURL`/`fallbackWallpaperSHA256`) on all monitors without an own entry, independent of the monitor count. With catppuccin on, the per-monitor wallpapers use the theme look (no blur, theme base colour); with catppuccin off they are blurred and dimmed by the scheme polarity.
* **`services.impermanence`**: Declares the paths bind-mounted from `/persist` for a host whose root is wiped at boot (the module does not wipe root itself), for important directories and files (NetworkManager, SSH, Bluetooth, Tailscale, etc.).
* **`services.locale`**: Per-category glibc locales as flat options (`address`, `identification`, `measurement`, `monetary`, `name`, `numeric`, `paper`, `telephone`, `time`), every default `en_US.UTF-8`, so an enabled module without values is all-US. They become `i18n.extraLocaleSettings` plus the display-manager `LC_TIME`; `LANG` stays `constants.mainLocale`. `LC_TIME` carries the clock, the date order, the day and month names and the first weekday together and cannot be split; the hosts set it to `en_IN` (12-hour AM/PM, day-month-year, English names, weeks start on Sunday) and the rest to `it_CH.UTF-8`. A UTF-8-only locale such as `en_IN` must be written as the bare name: `en_IN.UTF-8` fails the glibc-locales build (nixpkgs#256688). The SDDM themes and hyprlock ignore `LC_TIME` for their clock and have their own `use24HourClock` option.
* **`services.localsend`**: Installs LocalSend through nixpkgs `programs.localsend` and opens its TCP/UDP port 53317 in the firewall.
* **`services.resolved`**: Enables systemd-resolved as the system DNS resolver with DNS-over-TLS (opportunistic), Quad9 fallback DNS (`9.9.9.9`, `149.112.112.112`), and mDNS handed to avahi when it is enabled.
* **`services.sddm-astronaut`**: Configures the SDDM login manager with the Astronaut theme (`embeddedTheme`, default `astronaut`).
  * **Warning (sddm):** Without a display manager there would be no graphical login, forcing use of a TTY.
  * An assertion fails the build when `services.sddm-astronaut` and `services.sddm-pixie` are both enabled.
  * `use24HourClock` (default `false`): the greeter clock is `hh:mm AP` (12-hour); `true` keeps the theme's own 24-hour `HH:mm`. Independent of `LC_TIME` (the theme builds its Qt locale from `Locale=""`, which is the C locale, so the system locale never reaches it). The build fails if the `HourFormat` key is not found in the theme conf; `themeConfig.HourFormat` overrides both.
  * Sizes follow the screen: the font size is derived from the screen height (`height / 90`, the upstream 12 at 1080p) instead of a fixed 12pt, and the corner radius is tied to it, so the form keeps its proportions on any resolution. `themeConfig.FontSize` / `RoundCorners` win. With stylix on (default when a `background` is set), the accent pairs (hover marks, text on accent fills, warning, placeholder) are solved at build time for contrast on the form, for light and dark schemes alike.
* **`services.sddm-pixie`**: Configures the SDDM login manager with the Pixie theme and customizable styling options.
  * **Warning (sddm):** Without a display manager there would be no graphical login, forcing use of a TTY.
  * With a custom `background`, the theme colours come from the stylix palette and stay readable for any scheme (light, dark, mid-tone, pure white or black) and any wallpaper, by construction: at build time the module solves the login-card, field, popup and selected-row surfaces from the scheme background (darkened or lightened only as far as needed) together with one foreground colour (the palette text, else white or black), so every text state reaches 4.5:1 and every icon 3:1; the accent is used for icons, initials and the login button only where it keeps 4.5:1 on all those surfaces (else the foreground colour), with black or white text on top of it. The date, power bar and Num Lock notice use the accent when it clears 4.5:1 on the card over any wallpaper, else the foreground colour; a scheme text or accent too dark for the lock screen falls back to a light neutral; and the lock-screen dim is raised only as far as the clock and hint need. User `themeConfig` colour overrides win over all fallbacks.
  * `use24HourClock` (default `false`): the clock tiles are 12-hour (zero-padded, no AM/PM marker, so 09:05 AM and PM look the same); `true` is 24-hour. The theme computes the hour itself, so `LC_TIME` plays no role. The hardcoded date line is patched from month-before-day to day-before-month (`Thursday, 29 October`).
  * Polarity-aware: a light scheme gets a white scrim over the wallpaper, dark text and a light card; a dark scheme keeps the black scrim, light text and a dark card. If a `themeConfig` text or accent colour is unreadable under the scheme's own scrim but readable under the other, the scrim flips. The whole theme is laid out on a 1080-high canvas scaled to the screen, so the card and text keep their proportions at any resolution.
  * Only enable one sddm at any moment

* **`services.snapshots`**: A BTRFS snapshot retention automation system using Snapper to back up the filesystem on a configurable timeline (hourly, daily, weekly, monthly, yearly).
* **`services.swaync`**: A notification daemon and control center for Wayland compositors, with optional per-app notification muting rules.
* **`services.thermald`**: The Intel thermal daemon. Prevents CPU overheating by dynamically adjusting power limits before the kernel's thermal shutdown triggers. Independent of auto-cpufreq and tlp - can be enabled alongside either. ⚠️ Intel CPUs only; keep disabled on AMD hosts.
* **`services.tlp`**: An advanced power management tool that optimizes battery life by configuring processor governors and energy-performance policies based on power source. Forces `power-profiles-daemon` off while enabled. Mutually exclusive with auto-cpufreq.

#### Specializations (`specializations.`)

Specializations are bootloader entries that apply an alternative NixOS configuration overlay at boot time. Enabling the module adds the specialization; the base system is unaffected unless that boot entry is selected.

* **`specializations.deep-focus`**: Replaces the Hyprland, Niri and Mango autostart with browser, editor, file manager and terminal only and turns swaync DND on (effective when swaync is the active notification daemon). Useful for distraction-free work sessions.
* **`specializations.guest`**: Creates an ephemeral guest session using a tmpfs home directory (25% RAM, cleared on reboot), XFCE desktop, auto-login, all krit-specific services and mounts (tailscale, sshd, NAS, cloud, docker) switched off, and memory/CPU cgroup limits. Browsing-only: Firefox, mousepad, file-roller and a screenshooter; AI tools, compositors and shells, stylix/catppuccin, bluetooth, localsend, coffee, docker/podman and thunderbird are forced off. Includes a localized welcome dialog.
* **`specializations.safe-mode`**: A recovery specialization (tag `safemode-tty`) that disables all compositors, display managers and theming, boots to a TTY login where IceWM starts via `startx`, forces bash/xterm/nano as the survival shell stack, and installs a minimal rescue toolkit (mc, ncdu, parted, btrfs-progs, etc.).
* **`specializations.secure-travel`**: A hardened travel specialization with kernel sysctl hardening, GNOME-only desktop, Tor Browser plus LibreWolf with the Privacy profile as default (Zen, PWAs and the other browsers forced off), MAC address randomization, strict firewall, and Quad9 nameservers with opportunistic DNS-over-TLS. Tailscale stays on as the VPN (Mullvad exit node chosen by hand, untrusted `tailscale0`, no open firewall ports) and a home-manager user timer warns by notification while no exit node is set; it is advisory, not a kill switch. Bluetooth is present but not powered on at boot. Forces off nix-ld, nix-alien, claude-code, claude-desktop, codex, google-antigravity, headroom, herdr, localsend, docker, sshd, avahi and the NAS consumers, and locks the root account. Tor Browser is installed on x86_64 only.

* **`krit.programs.discord`** (common): the personal layer merged into `programs.discord` (which it enables): sets `mod = "equicord"` and the Equicord plugin set (`programs.nixcord.config.plugins`). `pinDms` is enabled without its per-user category list, which holds personal IDs and stays out of the public repo.
* **`krit.services.nas.{desktop,laptop}-borg-backup`** (NixOS): daily borgmatic backup to the NAS over its tailnet FQDN with a pinned NAS host key, at a fixed time (desktop 18:00, laptop 10:00, also on battery), a missed run is caught up later, the user's home and `/persist` are both backed up (docker, containers, flatpak, tmp, fscache and `.snapshots` under `/persist` are excluded), state is persisted under impermanence, full checks every 2 weeks. The Darwin twin follows the same pinning, FQDN and check policy.
* **`krit.system.ssh-config`** (NixOS): SSH client config for the NAS, the Gitea and GitHub hosts and, between the NixOS hosts, a `Host` entry for the other host (derived from the host list, never for itself) using the shared `id_github` identity. sshd also accepts the sops-managed `id_github.pub`, so the hosts trust each other without any key in the repository. Adds the `ssh-nixos-laptop` / `ssh-nixos-desktop` aliases (peer only) and, on the laptop only, `sw-laptop-with-desktop` and `build-laptop-with-desktop`, which run `nh os switch` / `nh os build` for the laptop with the desktop as build host.
* **`specializations.school`** (krit): ships the moodle-dl GUI (`moodle-dl --gui`, pinned to upstream master) with a desktop entry, NetworkManager VPN plugins and Wireshark capture. Declarative SUPSI Follow Me printing (queue `DTI_PRINTERS`, password from sops key `school_supsi_password`). School SSH keys and secrets live only in this boot mode.

### Darwin-Only Modules

These modules are active on Darwin (macOS/nix-darwin) hosts. Most are always-on infrastructure modules that handle platform integration and are not toggled by the user.

* **`common-configuration` (darwin)**: Core Darwin system defaults - sets hostname, enables Touch ID for sudo, configures macOS system preferences, and links system packages.
* **`home-packages` (darwin)**: Toggle, enabled by default. Installs the host's chosen browser, terminal, editor and file manager as system packages when the name is a nixpkgs attribute and no enabled module provides it; an unknown name gives an evaluation warning instead. `browser = ""` opts a host out of the browser package.
* **`nix` (darwin)**: Configures the Nix daemon for nix-darwin (flakes, store optimisation, `nixPath` pinned to the flake) and nix-index-database. Automatic GC is off because `nh` owns it; substituters come from `cachix`/`attic`.
* **`stylix` (darwin)**: Darwin-specific Stylix theming engine - applies the base16 palette and fonts (JetBrainsMono Nerd Font family: regular for monospace, Propo for sans/serif) across supported macOS/home-manager applications.
* **`user` (darwin)**: Declares the primary user account for nix-darwin (uid, home directory, shell).
