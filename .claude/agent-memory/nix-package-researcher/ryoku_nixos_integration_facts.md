Source snapshot: /home/krit/momentary/ryoku/Ryoku-on-NixOS-main (branch main, flake.nix of Ryoku-on-NixOS). Ryoku's own package universe is pinned to nixpkgs 56c02bc (2026-08-23) via input `ryokuPackagesNixpkgs`; our host nixpkgs is 2026-11-07. Do not follow `ryokuPackagesNixpkgs` from our flake (flake.nix:14-15 comment; docs/nixos.md:121-123). Ryoku's `nixpkgs` input is a compat input used only by its ISO outputs (flake.nix:9), so `inputs.ryoku.inputs.nixpkgs.follows = "nixpkgs"` is the one follow the upstream comment permits.

Key facts:
- Module is closed over Ryoku's own `self` and `ryokuNixpkgs`; the host passes nothing (flake.nix:138-142). `hermesAgent` is passed in but unused in nix/modules/ryoku.nix:1 yet still locks ~10 nodes (home-manager, uv2nix, pyproject-nix...).
- Module uses host `pkgs` for many runtime pieces (systemd, dbus, bluez, pipewire, iwd, chromium/firefox, fish, kitty) and Ryoku's pin for Qt/quickshell/mesa/PAM (ryoku.nix:33,39,44,1244-1245,2286).
- Mesa forced: hardware.graphics.package/package32 mkForce to Ryoku's 2026-08 mesa (ryoku.nix:1243-1246). Host intel-media-driver (hosts/nixos-laptop/system.nix:227-233) then sits on a different mesa.
- Forced compositor pkgs (mkForce, ryoku.nix:1227-1241): programs.hyprland.package/portalPackage, programs.niri.package. Our modules/nixos/toplevel/niri.nix:17,25 plain-assign pkgs.niri; Ryoku wins by mkForce.
- mkOverride 900 (beats mkDefault, loses to plain): users.defaultUserShell (1201-1206), services.displayManager.defaultSession (1685-1687), sddm.theme "ryoku" (1709-1710). A plain host value wins (nix/tests/display-manager.nix:76 proves custom theme wins).
- SDDM: enable mkDefault unless gdm/lightdm/ly/cosmic-greeter/greetd enabled (1696-1707). Our modules/nixos/services/sddm/*.nix set sddm.package mkForce kdePackages.sddm and plain theme; they would override Ryoku's theme.
- Plain assignments: xdg.portal extraPortals gtk/gnome/wlr + config.{hyprland,niri,mango} (1248-1294); polkit extraConfig is mkAfter (1362-1453); pipewire (1461-1471); gnome-keyring (1454) (consistent with our single-Secret-Service rule); programs.hyprland.xwayland (1235); environment.sessionVariables (1752-1781, no GDK_BACKEND; GDK_BACKEND set in ryoku/hyprland/modules/env.lua:48 and mango config).
- mkDefault: networkmanager (1476), docker enable from optionalApps "docker" (1576, default list includes docker, defaultOptionalApps 651-666), flatpak, bluetooth, upower, ppd, pkexec wrapper (1452), allowUnfreePredicate apple_cursor (1195). Host plain allowUnfreePredicate would silently break apple-cursor.
- nix.settings: only substituters/trusted-public-keys for ryotunes.cachix.org, mkAfter (1184-1192).
- Plain/mkAfter system files: boot.extraModprobeConfig (snd_hda_intel power_save=0, btusb autosuspend=0, bluetooth disable_ertm=1; 1639-1644); environment.etc."systemd/logind.conf.d/10-ryoku-lid.conf" (HandleLidSwitch=suspend, HandleLidSwitchDocked=ignore; 1654-1660). Drop-in beats services.logind.settings: conflicts with users/krit/nixos/specializations/home.nix:45-47 (HandleLidSwitch=ignore) when Ryoku is enabled there. udev rules ryokuUdevRules (480-556, mkAfter at 1648).
- Polkit grants YES for wheel + local + active on ryoku-power, ryoku-game-tune, ryoku-wifi-powersave, the system bridge (dns, wifi-backend, wifi-regdom, docker), sddm-theme-apply, and bluetooth.service restart (1362-1444).
- Materializer (nix/apps/ryoku-materialize.nix) writes: ~/.local/state/ryoku/nix/{backups,initial-backup-path,initial-backup-complete,seeded-wallpapers}; runs upstream `ryoku materialize` + `migrate-shell-config` (95-96); overwrites ~/.config/niri/{config.kdl,autostart.kdl} every run (161-164); runs ryoku-wm-{hyprland,niri,mango} apply on desktop.json (176-183); chmod u+w seeds (249-278); symlinks ~/.local/lib/qt6/qml/Ryoku/* (287-308); deletes legacy user units (349-364); seeds ~/Pictures/Wallpapers (once), ~/Pictures/ryodecors, ~/.local/share/ryoku/assets/brand; symlinks nautilus-python ext, ryoku/browser, spicetify (408-441).
- qylock materializer (nix/modules/ryoku.nix:256-358): rm -rf and replace ~/.local/share/quickshell-lockscreen and ~/.local/share/qylock/themes/clockwork/orbital; seeds ~/.config/qylock/theme once; PAM files fingerprint-denied.
- Initial backup copies every top-level entry of the packaged config tree from ~/.config (materializer 37-52): hypr, niri, mango, quickshell, kitty, fish, nvim, yazi, fastfetch, gtk-3.0, gtk-4.0, qt6ct, btop, starship.toml, wireplumber, ... (nix/packages/ryoku-desktop-data.nix:40-335).
- Overlap with our HM: programs.kitty (users/krit/common/programs/terminal-emulators/kitty.nix), programs.fish (modules/common/programs/shells/fish.nix), programs.neovim, programs.yazi, programs.fastfetch (3 files), gtk.enable (7 files), wayland.windowManager.hyprland (modules/nixos/programs/de-wm/hyprland/hyprland-main.nix:232), wayland.windowManager.mango (modules/nixos/programs/de-wm/mango/mango-main.nix:94), programs.niri.settings via niri-flake HM (modules/nixos/toplevel/niri.nix:23; niri-binds.nix:237; noctalia-main.nix:77). Ryoku writes niri/config.kdl and mango/config.conf every run: direct collision with HM-owned files.
- runtime-state-ownership.nix:60-99 assertion only protects ~/.config/ryoku (not user_edits), so HM collisions on hypr/niri/mango/kitty/fish evaluate fine and fail at runtime.
- Session starts: no uwsm anywhere in nix/ (grep 0). Compositor autostart runs ryoku-nix-session-start (nix/packages/ryoku-desktop-data.nix:63-76; body ryoku.nix:78-123): waits for login1 Type=wayland, Active, dbus-update-activation-environment, materialize || true, daemon-reload, restart ryoku-session.target, try-restart portals. ryoku-session.target binds graphical-session.target (ryoku.nix:1822-1842) with nothing in the module starting graphical-session.target directly (inference).
- Mango: provider Go at ryoku/wm/mango (~7k lines), pinned to 0.17.4 by overriding nixpkgs' 0.16.1 mango source (nix/packages/default.nix:50-60) - build ABI risk, unverified. Caps manifest 21 entries (ryoku/wm/mango/caps.go:57-80) with explicit absences: global shortcuts portal, cursor set, screen shader, plugins, focus grab, persistent screen capture (launcher frost solid), HDR, overview backdrop/column fill, workspace move to output. Mango session Exec=ryoku-mango-session is a bare name (ryoku.nix:237-245) and only materializes if config.conf is missing (212-233). docs/compositors.md has zero Mango mentions; Mango docs only in docs/nixos.md.
- Caches: ryotunes.cachix.org only (key QNocajCsVm/IAMb8LPOWJi72XwqiexW9ec0UqeXLpGs=). CI pushes .#ryoku-default-system to vars.CACHIX_CACHE (.github/workflows/nix-cache.yml:81-95). Locally rebuilt by design: niri patched (nix/packages/default.nix:44-48), quickshell patched commit 851ab0ea (flake.nix:71-80), mango 0.17.4 src override, hyprland with makeBinaryWrapper override (flake.nix:264-266). Cache.nixos.org coverage for 56c02bc: NOT verified.
- ryoku update = `sudo nix flake update <updateInput> --flake <updateFlake>` (nix/scripts/ryoku-nix-update:621-624), default updateFlake /etc/nixos (ryoku.nix:1155-1163). Pointing it at /home/krit/nix edits our flake.lock as root.
- Lock growth: Ryoku adds ~25 nodes, 4 extra nixpkgs revs (c59305 2026-10-01, 56c02bc 2026-08-23, 9fbb54 2026-08-26, 0954f7 2026-07-29) plus hermes subtree (home-manager, flake-parts, uv2nix).
- ryoku.dev: /, /nixos and /docs/nixos all return the same 146209-byte SPA shell; NixOS section not retrievable without JS.
- Impermanence risk (conditional): /var/lib/ryoku (SDDM payload, network state) and ~/.local/state/ryoku are not in modules/nixos/services/impermanence.nix persist list (grep found only /var/lib/sddm).
